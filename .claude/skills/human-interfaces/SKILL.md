# Human interfaces: how to avoid the AI look

## Where this list comes from (read this first)
The 30 tells below are from an Instagram reel ("30 reasons your site looks vibecoded", posted by @abhijayarora_ and aiwithabhijay, shown to Tarun on 9 Oct 2026). It is one designer's checklist of what people now read as machine-made. It is **not research**. Treat it as a strong heuristic: people who test Trickle already said "looks very AI generated", and removing these tells is cheap. Do not cite it as evidence that any single item hurts usability. Several items (for example a missing privacy policy, or no skeleton loaders) are about completeness more than looks.

## How to use this skill
1. Before designing: pick **one** accent colour, **one** typeface that is not on the list, a **tight** corner radius, and decide the page is **flat** (no depth effects). Write them down as tokens first.
2. While building: use real content from the product, in the product's own words. No filler.
3. After building: run the audit (below), then look at screenshots yourself. The script finds mechanical tells. It cannot judge whether the layout feels considered.
4. Say what you could not check (it only sees what a state renders; hover and loading states need a manual pass).

## The 30 tells and what to do instead
| # | Tell | Do this instead |
|---|---|---|
| 1 | Harsh gradients (hero, buttons, text) | Solid fills. If a fade is needed to hide scrolling content, use a solid bar. |
| 2 | Lucide icons everywhere | Words first. Use an icon only where it is faster than a word, from one set, or draw 3 to 5 custom ones. |
| 3 | Pure white background | Off-white or a tinted neutral (warm or cool). Dark mode: not pure black either. |
| 4 | Rainbow colouring | One accent plus neutrals. State colours (good, warning, bad) only for state. Categories can be tints of one hue, labelled. |
| 5 | Drop shadows | Separate with spacing, a 1px line or a slightly different fill. No glows. |
| 6 | Three feature cards in a row | Vary the layout: one big thing, a list, a table, a sentence. Do not repeat identical cards. |
| 7 | Emojis as decoration | None in UI copy. Real imagery or nothing. |
| 8 | Liquid glass, blur, frosted panels | Opaque surfaces. |
| 9 | Em dashes in copy | Use a full stop, a comma or a colon. Rewrite the sentence. (En dashes in number ranges, "4-6 pm", are fine.) |
| 10 | Inter, Geist, Space Grotesk | Pick another typeface with a reason (Public Sans, Source Sans, IBM Plex, a serif for warmth). Two weights are enough. |
| 11 | Coloured left stripe on cards | Use a label, a small dot, or nothing. |
| 12 | Fake testimonials | Never invent people or quotes. Use a real one, or leave it out. |
| 13 | Bento grids | A plain list or one column unless the content really is a mosaic. |
| 14 | Fake terminal window | Show the real product. |
| 15 | "It's not X, it's Y" copy | State the thing. Cut the contrast framing. |
| 16 | Checkmark bullets | Plain bullets or no bullets. |
| 17 | Three pricing tiers | Only if there are really three plans. Otherwise one price. |
| 18 | No real product demos | Show actual screens with realistic data. |
| 19 | Soft, large corner radius | 4 to 8 px on controls and cards. Pills only for true tags. |
| 20 | Purple and black | Choose a palette from the product's own meaning. Avoid the purple-on-near-black default. |
| 21 | No skeleton loaders | Where data loads, show a placeholder with the final layout. (Not applicable to a fully local app with no waiting.) |
| 22 | Radial glowing orbs | No background decoration. |
| 23 | Dot grids and grid backgrounds | Plain background. |
| 24 | Sparkle icons | Do not mark features as "AI magic". Describe what they do. |
| 25 | Animated arrows | No looping or hover-nudging arrows. Motion only to explain a change, kept short. |
| 26 | No terms | Include a Terms page, even a short honest draft. |
| 27 | No privacy policy | Include a Privacy page that says what is stored, where, and what is never read. |
| 28 | Hover animations (lift, scale, glow) | A plain colour change at most. Mobile has no hover anyway. |
| 29 | Neon colours | Reduce saturation. Aim for saturation under about 0.7 at mid lightness. |
| 30 | Basic pastel colours | Do not use the default pastel set. Take muted, slightly dull tones with a clear lightness order. |

## Positive rules (our additions, from the Trickle v17 work)
- **Less on each screen.** One main number, one picture, one action. If a screen has three equal cards, make one the answer.
- **Short plain words.** One idea per sentence, about eight words. Say "Recommended", not "even pace".
- **Real data.** Test with a realistic profile, a quiet one and a heavy one, not one tidy seed.
- **Colour is a signal.** If everything is coloured, nothing is. Pair colour with a word ("Over this week") so colour is never the only signal.
- **Tokens, then screens.** All colours, radii and fonts come from a handful of CSS variables. Check them before and after.

## The audit script
`scripts/audit.js` opens a page (or runs a list of states you give it) and reports tells that can be measured from computed styles: gradients, shadows, blur, large radii, left stripes, animations, the three fonts, purple, neon colours, five or more hue families on one screen, em dashes, emoji and check marks, "it's not X, it's Y" copy and hover transforms in the stylesheets.

```
# one page as loaded
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright node scripts/audit.js page.html --root body

# a prototype with several states (a module that navigates and calls snap('name') in each state)
node scripts/audit.js app.html --root '#phone' --states states.js --shots /tmp/shots
```
Exit code is 1 when anything is found, so it can sit in a test run. Trickle's example states file: `archive/session-workfiles/mockup17/tests/antiai_states.js`.

It cannot check: missing Terms or Privacy pages, fake testimonials, three-card layouts, real product demos, icon sets, loading states or whether the copy sounds human. Check those by eye with the table above.

## Review output
When reviewing someone's UI, report: the tells found (by number), where, the fix for each, and the items you could not check. Do not claim a UI "no longer looks AI generated". Say it no longer shows these tells, and that a person should look.
